## Shared implementation

`skill-packages.ts` checks graph references, cycles, and implicit dependencies on explicit-only skills. `skills.ts` applies the same invocation boundary to local edits, resolves the graph, and accounts for prompt context. Every selected V5 entrypoint stays complete in full, compact, and minimal representations. Only metadata and optional resources can shrink; insufficient mandatory capacity blocks execution instead of cutting later constraints. Per-package ceilings accommodate the complete entrypoint, but do not override the task's available context.

`skill-v5-quality.ts` detects repeated paragraphs within and across entrypoints, in addition to whole-body duplicates. The source-map and entrypoint prose checks cover all 180 packages. These are structural and editorial gates, not semantic grades. Organizational roots remain distinct when their responsibilities differ: literature synthesis is not a generic research orchestration task, threat modeling is not an implemented-code finding audit, and AI safety evaluation is not general model-quality testing.

The generic specialist template was replaced with domain-specific decisions and real-boundary verification. Shared task authority remains with the host and core skills rather than being repeated in every child. The communication parent owns the user's punctuation preference; `dash-free-writing` supplies a focused rewrite workflow and a read-only checker. Exact technical material, mathematical signs, source quotations and Markdown syntax remain protected.

The source refresh here rechecked the listed skill mechanisms and the pinned SkillsBench abstract, not every external domain page anew. Per-package source dates retain their actual earlier review dates. Bibliography punctuation cleanup does not count as fresh external research. The Matt Pocock revision was resolved through the GitHub API and its invocation file was read at that exact revision; no newer revision is implied.

## Evidence boundary

Package validation, routing regression results, author-owned positive and negative fixture controls, live subject runs, and independent blind judgments are different evidence classes. Never convert one into another. The current implementation does not make it impossible for a model to write poor prose; deterministic checks can detect scoped violations, while semantic fidelity and overall quality still require suitable evaluation. Qualification and competitive claims remain governed by the execution ledger and the masterplan's experiment contract.
