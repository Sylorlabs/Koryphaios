## evals.json

Lives at `<skill-dir>/evals/evals.json`. The master list of test cases for a skill. Start with just prompts; add assertions after the first run.

```json
{
  "skill_name": "example-skill",
  "evals": [
    {
      "id": 0,
      "prompt": "User's task prompt — realistic, with specifics like file paths, context, column names",
      "expected_output": "Description of what a good result looks like",
      "files": [],
      "assertions": [
        {
          "text": "Output file is a valid .docx",
          "type": "programmatic"
        },
        {
          "text": "Output contains the user's requested table",
          "type": "manual"
        }
      ]
    }
  ]
}
```

Fields:
- `id`: integer, unique within the eval set
- `prompt`: the exact task prompt a real user would type. Include specifics — file paths, context, column names, company names. Not abstract.
- `expected_output`: prose description of what success looks like
- `files`: array of input file paths the eval needs (relative to evals dir or absolute)
- `assertions`: array of objectively verifiable checks. `type` is `"programmatic"` (can be checked by a script) or `"manual"` (requires human judgment). Add these after the first run, not upfront.

## eval_metadata.json

Lives in each eval's run directory: `<workspace>/iteration-N/eval-<name>/eval_metadata.json`. Per-eval metadata for the current iteration.

```json
{
  "eval_id": 0,
  "eval_name": "descriptive-name-here",
  "prompt": "The user's task prompt",
  "assertions": [
    {
      "text": "Output file is a valid .docx",
      "type": "programmatic"
    }
  ]
}
```

`eval_name` should be descriptive — not just "eval-0". Use it for the directory name too.

## grading.json

Lives in each run directory: `<workspace>/iteration-N/eval-<name>/<config>/grading.json`. The grader's assessment of each assertion against the actual output.

```json
{
  "eval_id": 0,
  "eval_name": "descriptive-name-here",
  "config": "with_skill",
  "expectations": [
    {
      "text": "Output file is a valid .docx",
      "passed": true,
      "evidence": "File opens with python-docx, contains 3 paragraphs"
    },
    {
      "text": "Output contains the user's requested table",
      "passed": false,
      "evidence": "Output has 2 paragraphs but no table element"
    }
  ],
  "overall": "partial_pass"
}
```

Required fields in each expectation: `text`, `passed`, `evidence`. Do not use `name`/`met`/`details` — the viewer depends on these exact field names.

`overall` values: `pass`, `partial_pass`, `fail`.

## timing.json

Lives in each run directory. Captured from the subagent completion notification — this data is not persisted elsewhere, so save it immediately when the notification arrives.

```json
{
  "total_tokens": 84852,
  "duration_ms": 23332,
  "total_duration_seconds": 23.3
}
```

## benchmark.json

Lives at `<workspace>/iteration-N/benchmark.json`. Aggregated comparison across all evals and configs. Generated by the aggregation script or manually.

```json
{
  "skill_name": "example-skill",
  "iteration": 1,
  "generated_at": "2026-08-06T12:00:00Z",
  "configs": [
    {
      "config": "with_skill",
      "evals": [
        {
          "eval_name": "descriptive-name",
          "assertions_passed": 3,
          "assertions_total": 4,
          "pass_rate": 0.75,
          "tokens": 84852,
          "duration_seconds": 23.3
        }
      ],
      "aggregate": {
        "mean_pass_rate": 0.75,
        "stddev_pass_rate": 0.12,
        "mean_tokens": 84852,
        "mean_duration_seconds": 23.3
      }
    },
    {
      "config": "without_skill",
      "evals": [ ... ],
      "aggregate": { ... }
    }
  ],
  "delta": {
    "pass_rate_delta": 0.25,
    "token_delta": -12000,
    "duration_delta_seconds": -5.2
  }
}
```

When listing configs, put `with_skill` (or `new_skill`) before its baseline counterpart (`without_skill` or `old_skill`).

## feedback.json

Produced by the eval viewer when the user clicks "Submit All Reviews". Read this after each iteration to decide what to improve.

```json
{
  "reviews": [
    {
      "run_id": "eval-0-with_skill",
      "feedback": "the chart is missing axis labels",
      "timestamp": "2026-08-06T12:05:00Z"
    },
    {
      "run_id": "eval-1-with_skill",
      "feedback": "",
      "timestamp": "2026-08-06T12:06:00Z"
    }
  ],
  "status": "complete"
}
```

Empty feedback means the user thought it was fine. Focus improvements on test cases with specific complaints.

## trigger-eval.json

Used for description optimization. 20 queries — a mix of should-trigger and should-not-trigger.

```json
[
  {"query": "ok so my boss just sent me this xlsx file (its in my downloads, called 'Q4 sales final FINAL v2.xlsx') and she wants me to add a column that shows the profit margin as a percentage. The revenue is in column C and costs are in column D", "should_trigger": true},
  {"query": "write me a fibonacci function in python", "should_trigger": false}
]
```

For should-trigger (8-10): different phrasings of the same intent, some formal some casual. Include cases where the user doesn't explicitly name the skill. Throw in uncommon use cases.

For should-not-trigger (8-10): near-misses that share keywords but need something different. Not obviously irrelevant — genuinely tricky.
