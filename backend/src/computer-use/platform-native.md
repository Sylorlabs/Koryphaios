# Native computer adapter implementation notes

This is the implementation-level companion to `docs/computer-use.md`. Native APIs are **not** an OS security sandbox. App allowlists do not confine websites, documents, embedded applications, accounts, or downstream actions performed by an authorized application.

## Implemented capability boundaries

| Platform                   | Discovery and identity                                                                                                               | Observation                                                                                                                           | Input and focus                                                                                                                                                                                                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| macOS                      | Visible layer-zero CGWindow list; executable path from NSRunningApplication; window ID + process launch date + PID                   | macOS 14+ `SCScreenshotManager` using `SCContentFilter(desktopIndependentWindow:)`; never display capture                             | `AXPress` on a hit-tested element verified to belong to the uniquely bound target AX window. Text uses the currently focused element's settable `AXSelectedText`, **not** replacing the whole field or using clipboard. Secure text subroles denied. `AXRaise` + application activation for focus. |
| Windows                    | EnumWindows; QueryFullProcessImageName; HWND + process start time + PID                                                              | PrintWindow into a fresh bitmap for that HWND only; no CopyFromScreen or desktop fallback                                             | Semantic UIAutomation InvokePattern on an element whose process and ancestor native HWND match the target. SetForegroundWindow subject to OS restrictions. **Text insertion unsupported.**                                                                                                         |
| Linux X11                  | Local DISPLAY only; XRes 1.2 server-resolved local PID, same-user /proc executable and process start time; never trust `_NET_WM_PID` | XComposite named offscreen window pixmap only; never `XGetImage` on a window/root drawable. Requires existing compositor redirection. | Direct XRaiseWindow/XSetInputFocus with resulting focus check. **Click/text unsupported; AT-SPI not implemented.**                                                                                                                                                                                 |
| Wayland / XWayland session | Unsupported                                                                                                                          | Unsupported: no portal session implemented                                                                                            | Unsupported                                                                                                                                                                                                                                                                                        |

Keyboard and scroll actions are unsupported on **every** platform. The broad shared `interact` capability means at least one semantic action exists, not that arbitrary pointer/keyboard input works. Unsupported widgets/actions fail; there is no global synthetic-input fallback. Window-only observation can still include application-rendered embedded content and descendants. GPU/protected Windows applications may produce blank PrintWindow images even when the API reports success: the adapter does not claim it saw protected content.

macOS image dimensions are set to window bounds in points (one output pixel per point), with window shadow disabled; click coordinates use the same window-relative points. Windows uses DPI-aware window-relative pixel coordinates. Linux capture supports standard RGB masks and at most 4,194,304 pixels; macOS/Windows limit to 16,777,216 pixels. All helper output has an additional 24 MiB transport ceiling.

## Prerequisites and packaging

- All three helper programs are **static TypeScript string exports**, embedded by Bun bundling/compilation. No `import.meta.dir`, workspace scripts, relative helper files or installed source tree are needed. Runtime helper files are materialized in a private random temporary directory (0700 on POSIX; scripts 0600), removed on normal host exit. Hard host termination can leave these **source/binary-only** directories behind. Captured images never go to files.
- macOS currently requires `/usr/bin/swiftc` plus Xcode Command Line Tools/SDK with ScreenCaptureKit and the macOS 14 screenshot APIs. The first operation compiles a temporary native executable; cold compilation can take tens of seconds (120-second compilation limit), so opening status before the first action is recommended. Default adapter instances share preparation. Executing a compiled Bun host still requires this toolchain. A prebuilt signed-helper packaging integration is **not** implemented.
- macOS Screen Recording and Accessibility permissions are independently preflighted. No consent request API is called. Grant/revoke permissions in System Settings for the responsible host/helper as macOS identifies it. Runtime-built helpers do not supply a stable signed app bundle identity; installer/signing/TCC UX must be validated before production distribution. Do not promise that a host grant will automatically carry across builds.
- Windows requires the system Windows PowerShell 5.1 executable, desktop .NET `System.Drawing`, `WindowsBase`, UIAutomation assemblies, and an interactive desktop session. The helper uses `-NoProfile -NonInteractive -File`; **execution policy is respected**, never bypassed. `Add-Type` compiles only static shipped C# declarations. No UAC elevation, UIAccess bypass, or secure-desktop support is attempted.
- Linux requires `/usr/bin/python3` (isolated `-I` mode), `libX11.so.6`, `libXres.so.1` with XRes 1.2, local X11 DISPLAY and same-user `/proc` access. Observation additionally needs `libXcomposite.so.1`, Composite 0.2+, and a compositor that already redirects the target window. Common distro package names include `python3`, `libx11-6`, `libxres1`, `libxcomposite1` (Debian-family) or corresponding `libX11`, `libXres`, `libXcomposite` packages. Missing capabilities/dependencies fail closed. No packages are auto-installed.
- `WAYLAND_DISPLAY` or `XDG_SESSION_TYPE=wayland` disables the Linux adapter, even if DISPLAY is also present. Portal ScreenCast window selection plus PipeWire stream identity and RemoteDesktop/libei input grants would need a separate consent/session implementation. Merely installing AT-SPI or portals does not enable support.

## Protocol and checks

`platform.ts` only sends validated, reconstructed JSON requests on stdin to fixed commands with fixed arguments, no shell interpolation. Only system interpreter paths are used. The environment omits `LD_PRELOAD`, `DYLD_*`, Python path hooks and other injection variables. Request text is data, including shell metacharacters.

Targets are enumerated before operations, checked again inside native helpers, and checked after capture before returning PNG bytes. PID, executable-derived app identity and process-start-bound window IDs must match; titles are never authorities. macOS AX-to-CGWindow binding has no public native window-ID attribute, so it requires one unique bounds match and refuses ambiguity. Identity checks reduce stale-target/PID-reuse risks but are not atomic OS transactions and do not protect against malicious same-user desktop clients or replacement of an approved executable on disk.

Helpers have bounded stdout, timeout and abort termination. POSIX helpers run in a process group so abort also terminates compiler children; Windows terminates the helper process. An action accepted by another application cannot be rolled back merely by killing the helper. Status is a dependency/consent probe and never enumerates application titles. Native helper source/binary preparation is shared by default adapter instances; a stopped caller cannot proceed to a later native action after preparation finishes.

## Verification performed

- `bun test backend/src/computer-use/platform.test.ts`: 18 passing tests; off-OS tests use injected JSON helpers and the currently running Bun executable, **not** installed Swift/PowerShell/Python/native libraries.
- `bun run --cwd backend typecheck`: passed.
- Built and ran a standalone Bun `--compile` smoke program from `/tmp`; all three native sources were embedded and Wayland status failed closed without a source-tree dependency.
- On the current Mac, compiled the real Swift helper and called **status only**. Result: `discover`, `interact`, `manageWindows`; correctly omitted `observe` because Screen Recording consent was absent. No capture, input, focus change or application discovery was performed.
- Parsed embedded Linux code with Python AST and ran its explicit Wayland rejection branch; this is **not** Linux native-runtime verification.
- Windows native runtime, Linux X11/XRes/XComposite native runtime, macOS actual capture/input and TCC installation flows remain **unverified**. Use the manual acceptance matrix in `docs/computer-use.md` on isolated test desktops before claiming release readiness.

## Authoritative references reviewed

1. Apple [SCScreenshotManager](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager) ([machine-readable documentation](https://developer.apple.com/tutorials/data/documentation/screencapturekit/scscreenshotmanager.json)): introduced macOS 14, captures a single frame through a content filter.
2. Apple [AXUIElement](https://developer.apple.com/documentation/applicationservices/axuielement) ([machine-readable documentation](https://developer.apple.com/tutorials/data/documentation/applicationservices/axuielement.json)): accessibility object hierarchy, geometry and supported actions.
3. Microsoft [UI Automation overview](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-uiautomationoverview): provider trees, properties and control patterns; accessibility does not override cross-user boundaries.
4. Microsoft [PrintWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow): synchronous, target-application-rendered HWND capture, motivating an external process timeout.
5. Microsoft [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput): global keyboard/mouse input stream and UIPI restrictions; deliberately not used.
6. Microsoft [SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow): foreground restrictions can refuse activation, even when nominal conditions hold.
7. X.Org [X Resource Extension 1.2](https://www.x.org/releases/current/doc/resourceproto/resproto.txt): client IDs resolve resource owners; LocalClientPid is server-resolved and local-only.
8. X.Org [Composite protocol 0.4](https://www.x.org/releases/current/doc/compositeproto/compositeproto.txt): NameWindowPixmap references per-hierarchy offscreen storage; fails for unredirected/invisible windows, includes window descendants, and must be freed.
9. GNOME [AT-SPI 2 API](https://docs.gtk.org/atspi2/): Accessible/Action/EditableText interfaces; documentation recommends AccessibleAction over global generated mouse events. Researched, not implemented here.
10. freedesktop.org [ScreenCast portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.ScreenCast.html): user-selected window/monitor streams, PipeWire remote and lifecycle; source defaults must not be confused with window-only capture.
11. freedesktop.org [RemoteDesktop portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html): independently granted input devices, user consent/session lifecycle and preferred EIS transport. Not an application input sandbox.
