## Exact commands (do not run here)

Source: `scripts/run-skill-v5-blind-review.ts`, `scripts/run-skill-v5-blind-review-campaign.ts`.

### Prepare sealed anonymous assignments (authoritative current pair binding)
```bash
bun run scripts/run-skill-v5-blind-review.ts --prepare-only [--skill=<name> ...] [--max-per-skill=<n>] [--retry-failed] [--concurrency=1-8]
```
- Writes sealed pending artifacts under `.koryphaios/skills/blind-reviews/pending/` (`<assignmentId>.prompt.txt`, `<assignmentId>.private.json`, schema v3). Existing seals are **not overwritten**.
- `--dry-run` is also supported for planning.

### Read-only validation of an external reviewer envelope (no ledger persistence)
```bash
bun run scripts/run-skill-v5-blind-review.ts --validate-only=<path/to/import.json> [--skill=<name> ...] [--allow-native-stage]
```
- `--validate-only` and `--ingest` are mutually exclusive (`run-skill-v5-blind-review.ts`: throws if both set).
- Validates schema, prepared assignment binding/hashes, current eligibility, steward separation, judge schema/rubric/source-mismatch, and (if native) archived native evidence. Increments `validatedReviews`; does **not** persist evaluation runs.

### Ingest a validated external reviewer envelope (coordinator-owned)
```bash
bun run scripts/run-skill-v5-blind-review.ts --ingest=<path/to/import.json> [--skill=<name> ...] [--allow-native-stage] [--retry-failed]
```
- Persists the with-skill arm as a `blind-review` run (`evaluator=blind-review`, `harnessVersion=v5-blind-semantic@8`, `protocolVersion=3`, `evaluatorId=independent-blind-semantic-v7`) with `evaluatorProvenance` (agent/provider/model, assignment, blind-to, prompt/artifact/output hashes, assignment file hash, reviewer agent evidence; native evidence refs only for native stage). Writes protected assignment JSON under `.koryphaios/skills/blind-reviews/` (or native retained-evidence dir) and records via `recordSkillEvaluationRuns`.

### Campaign (stages evidence only; never ingests)
```bash
bun run scripts/run-skill-v5-blind-review-campaign.ts [--skill=<name> ...] [--reviewer-adapter=<adapter|path>] [--reviewer-model=...] [--max-per-skill=1|2] [--max-assignments=<n>] [--max-reviewer-attempts=1-5] [--reviewer-wall-clock-ms=30000-600000] [--concurrency=1] [--retry-failed] [--dry-run] [--diagnose-reviewer]
```
- Passing `--ingest`/`--ingest=*` throws: “The campaign cannot ingest evaluations; use the coordinator importer”. After staging, it runs `run-skill-v5-blind-review.ts --validate-only=<envelope>` (adds `--allow-native-stage` only for native reviewer adapter) and writes `review-attestation.json` as `unimported`.

## Required preconditions (from code)

1. **Explicit mode required.** Direct V5 blind judging is disabled unless `--prepare-only`, `--validate-only=<result.json>`, `--ingest=<result.json>`, `--dry-run`, or `--summary` is passed (`run-skill-v5-blind-review.ts`).
2. **Envelope validity.** `schemaVersion: 1`; `reviewer.agentId/provider/model` non-empty strings; `reviews` is an array. Each review has `assignmentId` and `output` (native stage requires string output). `MAX_BLIND_IMPORT_BYTES` bounded reads apply.
3. **Prepared assignment must exist and remain sealed.** `pending/<assignmentId>.private.json` schema v3, matching ids/hashes, `promptPath` bound to pending prompt, prompt SHA-256 unchanged. Artifact hashes and prompt tail binding (`TASK` onward) must match the *current* anonymous pair artifacts; arm mapping must equal sealed randomized order.
4. **Current eligibility / no stale pair.** The assignment’s exact skill/scenario/pair/revision/contract must still resolve to an eligible current pair (`eligible` built from selected V5 packages, current active valid skill revisions, eligible evidence, matching source contract: `evaluationContractVersion/Hash`, materializer/scorer ids). Excluded evidence for the pair blocks import (`evidenceEligibility.excludedEvidence`).
5. **Independent reviewer / steward separation.** Registered steward must exist (`getSkillSteward`) and `envelope.reviewer.agentId !== steward.agentId` or import throws “cannot blind-grade its own work”.
6. **Judge output validity.** Parseable JSON (with limited repair paths), valid artifact scores (`passed` bool, `quality`/`verification` 0..1, `integrityFailure` bool, string evidence), preference `A|B|tie`, string rationale. Must not violate evaluator-owned routing/hierarchy/pairing boundary (`findBlindJudgeRubricViolation`) or contradict source evidence (`findBlindJudgeArtifactMismatch`).
7. **Native-stage only when qualified.** `nativeStageEvidence`/native identity requires `--allow-native-stage` and fresh archived evidence; envelope must not change during validation; only one review per native envelope. Native verification checks archived raw events, host receipt, sealed prompt/profile refs, protected roots, MAC stage profile, and exact completion bindings (`blind-review-native-import.ts`).
8. **Persisted provenance only after ingest.** A staged `review-attestation.json` with `persistedReviews: 0` is **not** persisted evaluator provenance. Ingest creates the assignment record + run evidence refs; eligibility/qualification logic later depends on recorded runs and provenance rules (`selectEligibleSkillEvaluationEvidence`, pair matching, reviewer/steward constraints reflected in recorded runs).

- **Unqualified route/isolation:** logfare-stateless host receipts explicitly report `osIsolationVerified: false`, `upstreamIdentityVerified: false`, `signed: false`. The campaign’s generic-adapter path states route/isolation is unverified and stage-only evidence requires coordinator qualification before ingestion. Treat as *evidence for coordinator review*, not qualified independent isolation.
- **Not native-archived evidence:** no `nativeStageEvidence` in these envelopes; `--allow-native-stage` is not the applicable path. Do not confuse with the stricter host-observed native empty-tool/macOS private-root profile.
- **Temp prompt snapshot paths in attestations** point to `/private/var/folders/.../kory-v5-blind-review-*` from staging time; the durable staged copies in this output directory are the coordinator-facing evidence bundle.
- **MLOps duplicate pair:** `mlops-2026-11-07-failed` and `mlops-2026-11-07-retry` target the same `assignmentId`/`pairId`. Both judge outputs fail. Importing one would not make it passing; importing strategy for duplicate/retried staged judgments should be decided by the coordinator against current pending seals and ledger state.
- **Audio-production integrity signal:** artifact A contains `integrityFailure: true` due to an unsupported compliance claim. Qualification should not proceed mechanically on a passing-looking artifact B without resolving arm identity and assessing the integrity finding.
