# Task routing

Routing classifies; it grants no execution authority. Route from the requested outcome and positive evidence: task kind, medium, topology, language/runtime, toolkit, domain, and repository state. Ignore incidental, historical, pasted, or negated technology mentions.

Prefer the smallest specific bundle. Add only required dependencies, preserve near-neighbor boundaries, and surface conflicts. Re-route only after material task or evidence changes.

Use broader skills for shared principles and children for their narrower responsibilities. Parents do not authorize unrelated specialist work. Facets add a relevant perspective without replacing the selected skill or its evidence requirements. Complete selected entrypoints must remain available under context pressure; trim optional resources or report insufficient capacity rather than silently discarding constraints.

Report context cost or omitted guidance when budget pressure matters. For source-sensitive routing details, read [references/sources.md](references/sources.md).
