# Verification workflow for bounded gRPC/protobuf work

Use this sequence when implementation, tests, and reporting share a limited execution budget. Complete all contract requirements; order the work so the compatibility failures with the highest risk become visible while they can still be fixed.

1. **Identify the changed contract.** Inspect the existing schema or stream implementation and the requested target state. Separate protobuf field evolution from streaming lifecycle changes; include both only when the task changes both. For staged migrations, inspect every requested schema stage at the outset.
2. **Find an executable check early.** Confirm the project's available test command and whether its protobuf generator, descriptor tooling, and type checker actually exist. Run a focused baseline when useful. Missing optional tooling is a reporting limitation, not proof that generated code or wire behavior works.
3. **Make one complete compatibility pass.** Update the interdependent contract artifacts before broad cleanup. Run the smallest tests that exercise the changed behavior, correct failures, and rerun the affected path. Do not let speculative hardening defer the first runnable check.
4. **Confirm and report.** Once required checks pass, capture a representative final run and any required generation/compilation evidence. Avoid repeated stress runs without a concrete unresolved failure. State which checks passed, failed, or could not run, and which requested behaviors remain unverified.

For an RPC boundary change, identify the target authority, resolver or service configuration, fully qualified method route, transport credentials, metadata policy, interceptor order, and terminal status owner before testing the handler. Treat security and route checks as observable behavior: include an allowed call, an authentication or authorization denial, an exceeded limit, a route mismatch, and an independent check that denied calls created no handler or downstream effect.

## Focus the first checks

| Changed surface                            | First implementation pass                                                                                                                                                                                                            | Early runnable evidence                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Protobuf field evolution                   | Keep the same fully qualified declaration identity for revisions made in place; update the active schema and any later schema that reserves removed field numbers and names; update the normal application encoder/decoder together. | Check live and later schema identities and reservations. Exercise compatibility between an old reader and a new writer and between a new reader and an old writer, precedence between legacy and replacement fields, unknown fields, and known and unknown enum numerics through an actual decode and encode pass, including multibyte values. |
| gRPC streaming lifecycle                   | Establish bounded buffering and producer backpressure, termination on cancellation or deadline, downstream status preservation, half close behavior, and cleanup.                                                                    | Run focused tests for slow readers, cancellation, deadlines, errors, half close, and teardown. Add a bounded stress run if a timing risk or a resource cleanup risk remains unexplained.                                                                                                                                                       |
| RPC boundary, interceptor, or routing work | Establish the ordered authentication, authorization, limit, telemetry, and error layers; bind them to the authenticated target and fully qualified method route.                                                                     | Run allowed and denied calls, malformed or oversized metadata and messages, route mismatch, peer verification, redaction, preserved status details, and no effect after denial. Label an in process harness separately from a real channel or TLS observation.                                                                                 |

Checks on generated clients and executable interoperability checks answer different questions. Run both when the task and available tools require them; do not substitute one for the other. A final summary should make any unperformed check visible instead of inferring its result from passing adjacent tests.
