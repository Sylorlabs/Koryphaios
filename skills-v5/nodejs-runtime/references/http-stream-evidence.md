# HTTP stream, disconnect, and shutdown evidence

Use this when a Node streaming endpoint must prove bounded producer reads, client disconnect handling, or server cancellation. A test whose `Writable` stays in memory checks stream behavior but does not establish HTTP socket behavior. A script that was written or parsed but could not listen has not executed an HTTP test.

## Exercise native Node HTTP with a blocked consumer

1. Run the actual exported implementation under the supported native Node release and module mode. Start a `node:http` server on a loopback ephemeral port, wait for `listening`, and handle server `error`. Retain the exact test command, Node version, input parameters, and results. Use `try/finally` for closing the server, clients, and remaining connections, including failure paths.
2. Feed the real CSV transform from a counted `Readable` that simulates a database feed into `ServerResponse`, with a response larger than socket and stream buffers. Count _actual_ source reads. Instrument `ServerResponse.write()` results and its `writableLength` without changing production flow control. Pause the client `IncomingMessage` before consuming the body and hold it paused long enough to observe blocked writes.
3. **While the HTTP client remains paused**, sample source reads, queued response bytes, and calls where `write()` returned `false`. Record the observation point and the producer high water mark reached by each stream. The reads and queued bytes taken _after_ `drain` or after the client resumes cannot establish bounded reads during backpressure. Resume the client, collect the complete body, and compare the received byte count and content with the expected CSV output.

## Verify two independent cancellation paths

4. On a new request, close the client connection **in the middle of the response**. Observe the server response's premature `close`, propagate an `AbortSignal` to the pipeline, and record source reads at abort and after the pipeline settles. `readsAfterAbort` is the final read count **minus** the count at abort; verify zero additional reads and destruction of both source and destination. Distinguish premature close from a normal finished response.
5. On another request, abort the controller the server owns **while the HTTP socket is still open**. Record that the signal fired before the socket closed, then check both streams are destroyed and that no additional source reads follow cancellation. A disconnect test alone does not exercise cancellation initiated by the server.
6. Independently inject source/database, transform, and destination failures. Exercise empty output, normal completion, and shutdown; check that no successful response left pending writes, and that no active pipelines or open connections remain after cleanup. Record expected teardown of a partial response separately from normal `writableFinished` completion.

## Record only executed evidence

7. Keep a run receipt with the transport (`http`), execution command, Node version and ESM/CommonJS mode, total rows, sampled count of paused reads, buffered bytes, false writes, received bytes, both cancellation read deltas and resource states, error cases, and shutdown counts. Mark a case `pass` only when its assertions actually ran. Retain the harness output so summary fields are traceable to the same run. Use `measured` only for values observed in an executed native Node HTTP session; an independently reported result is evidence of that independent run, not a local measurement.
8. If loopback `listen()` fails (for example `EPERM` in a restricted runner), preserve the error and mark the **HTTP** cases unavailable. A passing Bun test or a Node test without sockets remains useful partial evidence. Run the harness in an authorized environment that permits loopback listening when available; until then, leave HTTP and socket cleanup claims unverified rather than filling counters with zeros or inferred values.

9. When the evaluation workspace includes `scripts/collect-evidence.mjs`, run `node scripts/collect-evidence.mjs stream` immediately after the focused fix and regressions. It runs Bun regressions and the native Node HTTP probe, then writes `.kory-eval/node-stream.json` from that same executed HTTP receipt only when **all** checks pass. Keep the `KORY_NODE_HTTP_PROBE` output with the report. If `listen()` returns `EPERM`, this command cannot produce measured HTTP evidence: retain the exact failed probe log, leave the HTTP report absent, and report the HTTP cases unavailable. Do not turn native output that exercises only the source, runs in memory, or otherwise bypasses HTTP into candidate HTTP measurements, copy an evaluator's independent counters into the candidate's report, or claim that socket tests ran because independent grading can run them elsewhere.
