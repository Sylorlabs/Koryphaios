# Accessibility failure modes and acceptance probes

Use this when a design names accessibility features yet leaves a critical task inaccessible. These are **requirements and proposed checks**, not successful test results. Verify actual toolkit, app build, device, operating system, input and assistive technology versions before claiming behavior. Preserve identifiers supplied by the workspace's scope file rather than replacing them with this guide's prose.

## Editors with asynchronous and virtualized UI

| State or trigger                                                                 | Substantive error                                                                                                    | Design requirement and falsifiable check                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A project tree lazily loads or recycles a selected/focused item during filtering | Equating a reused visual row with the old logical item, or requiring focus to remain on a node that no longer exists | Give items stable logical IDs; specify tree level/position/expanded and selected state through the actual toolkit. When the focused item still exists, restore its identity after realizing it. When it is filtered out, explicitly choose an available result or the filter, announce the change, preserve a valid selection or clear it with explanation, and restore keyboard navigation. If the user is typing in the filter, leave editing focus there. Probe filtering while focused, selected, and typing separately; fail on focus loss, unrelated item announced, or recovery requiring a pointer. |
| New diagnostics arrive while a document has keyboard focus and an active caret   | Sending every update into focus, or silently changing only a colored badge                                           | Keep caret and focus stable; make severity, affected location, new/cleared status and remedy retrievable via an accessible diagnostics view. Prioritize genuine blockers, aggregate repeated updates and allow review on request; verify a path usable without a pointer to the diagnostic and back. Probe rapid arrivals/clears as well as one blocking error; fail on stolen caret, missing location, or announcement flood.                                                                                                                                                                              |
| A conflict dialog replaces an editor containing uncommitted edits                | Dialog labels exist but cancellation loses edits, traps interaction, or returns focus to a destroyed editor          | Expose local/remote versions and decision consequences through named actions. Ensure accessible navigation, cancel/undo and valid focus return to a retained editor location. Retain a recoverable local revision until resolution is confirmed. Probe cancel, commit, undo and restart; fail on lost changes or focus returning to a missing control.                                                                                                                                                                                                                                                      |
| Save is interrupted after a local edit but before remote confirmation            | Reporting "saved" from a local write, or restoring an earlier remote version over newer local work                   | Distinguish dirty, local durable, sync pending, sync failed and server confirmed with status communicated beyond color. Keep an identifiable local revision and retry/reconcile route; reserve "synced" for acknowledged remote commit. Probe restart at the interruption boundary and compare revision identifiers/content before and after.                                                                                                                                                                                                                                                               |
| Scaling, system contrast or reduced motion is enabled during a live update       | Adapting text decoration while clipping actions or hiding async progress                                             | Reflow using the actual platform's scaling mechanism, keep error/dirty/conflict actions operable, provide severity conveyed beyond color, and replace orientation that depends on motion with readable state transitions. Probe full task completion at the product's supported settings, including long localized content.                                                                                                                                                                                                                                                                                 |

For a web tree, the WAI-ARIA Authoring Practices tree pattern distinguishes selection and focus; dynamically loaded nodes may need set position/size semantics. **Those ARIA attributes do not become native API requirements.** For Windows native controls, investigate the toolkit's UI Automation Selection/Grid and ItemContainer/VirtualizedItem patterns. For macOS native controls, investigate AppKit/NSAccessibility roles, focused elements, selection and change notifications. Demand a discovery question when the actual toolkit or its accessibility bridge is unknown; never assert that one of these APIs is implemented merely because the host OS matches.

## Games primarily operated by controller

| State or trigger                                                       | Substantive error                                                                                                            | Design requirement and falsifiable check                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Confirm is remapped onto Back or Pause                                 | Applying a binding that strands essential menu actions                                                                       | Stage and validate the entire binding map before commit; expose conflicts and a reachable resolve/cancel/reset route, ideally usable by an alternate device or single action input. Change prompts when saved bindings change; retain last usable configuration. Probe navigation, confirmation, escape, persisted reload and rollback after an intentional collision.      |
| Controller disconnects during a timed attack                           | Assuming a controller reconnect or a global pause always saves the player                                                    | Show input loss state by available channels, identify feasible replacement input, and give an intentional recovery/respawn path. Define offline pause or timing assistance only where supported; for online play state that the shared simulation continues, and explain any local safety assistance or game state consequence. Probe reconnect before/during/after danger. |
| An offscreen urgent sound has no visible counterpart                   | Captioning only "sound", with no way to decide where or when to act                                                          | Convey threat/source, relative direction, urgency and response window in a perceivable visual or suitable alternate channel; make the cue identifiable and persistent enough to use at supported settings. Probe muted audio during the actionable window; fail when location or urgency cannot be recovered.                                                               |
| A brief combat telegraph signaled only by red signals attack           | Adding another color or a brief generic vibration with no usable lead time                                                   | Provide distinguishable shape/pattern/position plus audio or haptic alternatives appropriate to the audience; tune cue duration, contrast and user timing options without silently changing online competitive rules. Probe configurations independent of color and those using reduced motion against the actual attack window.                                            |
| Health, stamina or ammunition change rapidly                           | Narrating each tick until important warnings become inaudible                                                                | Expose the current value on demand and prioritize critical thresholds or changes relevant to the next action; coalesce routine updates, control speech verbosity and separate narration from effects audio where available. Probe rapid updates while another urgent cue occurs.                                                                                            |
| A long upgrade tree changes page, filter or purchase state             | Losing the selected upgrade, hiding prerequisites at large text, or purchasing through a shortcut without clear confirmation | Preserve logical upgrade identity across virtualization/pagination, announce cost/availability/prerequisites, keep navigation without a pointer and confirm/cancel/undo reachable, and return to a predictable item after purchase. Probe selection, large text, unavailable items and rollback.                                                                            |
| Online cooperative requires voice instructions and has a settings menu | Treating typed chat or an inaccessible "Pause" as an equivalent route                                                        | Provide quick pings/presets or text that conveys the needed team action and urgency through a usable alternative input path. Show that shared time continues while menus open, indicate live risks, and orient the player on return. Probe a team decision made without voice and the shared game clock during settings.                                                    |

## Recording evidence honestly

### Make the structured record prove a task path

For a bounded JSON deliverable, cross-check the source's exact task and channel IDs against the saved arrays rather than relying on keyword coverage. The following are **illustrative planned requirements**, not real implementations or observed tests:

```json
{
  "taskContracts": [
    {
      "taskId": "navigate-project",
      "goal": "Reopen the intended file from the filtered tree by keyboard without selecting a recycled row",
      "barrier": "Filtering removes the focused item while the tree reuses visual row elements",
      "alternative": "Keep focus in the search field while typing; when the user returns to the tree, navigate the surviving items by stable file ID with their full names and positions announced",
      "failureState": "A recycled row retains a stale selected ID and opens an unrelated file",
      "recoveryInvariant": "Selection is rebound to the surviving logical ID or explicitly cleared, the user is informed, and keyboard navigation can resume without losing the filter text",
      "owner": "Project tree and accessibility bridge"
    }
  ],
  "verificationMatrix": [
    {
      "taskId": "navigate-project",
      "platform": "macOS; application build and toolkit to establish at execution",
      "assistiveTechnology": "VoiceOver; version to establish at execution",
      "input": "Keyboard and VoiceOver navigation",
      "expectedObservation": "After the focused item is filtered out, the announced surviving target matches the selected logical file ID and no unrelated file opens",
      "method": "In a seeded large tree, select a named file, type a filter that removes it, navigate results and open the reported target; compare file ID, focus, selection and spoken output",
      "status": "planned",
      "observedResult": null,
      "evidenceRef": null,
      "risk": "No application build or VoiceOver session has been exercised"
    }
  ]
}
```

This is **one incomplete fragment**, not a substitute for all tasks, channels, platforms, alternate input paths or recovery probes in the actual scope. A game channel record likewise needs `channelId`, what that channel communicates, a separate usable alternative and `deliveryBehavior` that preserves direction, urgency and response time when audio is muted. For example, a directional alarm requires a persistent on-screen source/direction and urgency cue with a usable lead time, rather than an undifferentiated caption saying “sound.” A remap contract must describe how Confirm/Back/Pause conflicts are rejected before saving and how the player can reset without the lost control.

### Evidence status review

| Status     | Permitted claim                                               | Required evidence state                                                                          |
| ---------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `planned`  | Test procedure and expected result have been designed         | `observedResult: null`, `evidenceRef: null`                                                      |
| `untested` | A specific device/input/AT combination has not been exercised | Null result and reference; named remaining combination                                           |
| `blocked`  | A specific attempted run could not start or finish            | Exact runtime/device/permission/dependency obstacle and attempted setup; no fabricated pass/fail |
| `failed`   | An executed procedure produced the documented defect          | Actual failure observation, environment and retained evidence                                    |
| `passed`   | An executed procedure produced the expected behavior          | Actual observation with retrievable evidence and a matching environment                          |

Do not promote an anticipated announcement into a purported VoiceOver/NVDA transcript or turn a deterministic JSON scorer pass into a passed device test. Static fixtures and proposed oracles can validate the _shape_ of a design; they do not independently verify product behavior. If a check cannot be run, say exactly what was unavailable and keep the corresponding behavior unverified.

## Live browser and device evidence gate

When a design is handed to `accessibility-verification`, the evidence row must identify the
actual runtime before it can support a live claim. Record the application/build, operating
system and device (or a declared supported emulator), browser where applicable, input path,
assistive technology and version, accessibility settings, fixture/content state, steps,
expected observation, observed result, timestamp, and a retrievable artifact reference.
Use the following boundary when deciding whether a result is live evidence:

| Target claim                                 | Required live observation                                                                                                                                                                                                                                   | Does not establish the claim                                                                                                            |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Browser keyboard, focus, scaling, or reflow  | The named browser and app execute the task with the stated input; visible focus, return focus, actual browser zoom/reflow, and the relevant failure/recovery state are captured.                                                                            | A source review, a narrow viewport substituted for browser zoom, a Playwright assertion, or a synthetic accessibility tree.             |
| Browser screen reader output                 | The named OS/browser/app and screen reader actually announce the tested focus, busy, error, and recovery transitions; retain a tester transcript or recording tied to the input steps and versions.                                                         | `aria-live`, expected speech text, a tree snapshot, or a different screen reader silently substituted.                                  |
| Mobile accessibility service or switch input | The named device/runtime and app are exercised with the specified service and input configuration separately; record spoken state, accessibility focus, traversal/activation, return focus, and maximum supported scaling with representative long content. | Compose/DOM semantics, generated events, or a synthetic TalkBack/Switch Access row without service interaction.                         |
| Native editor, game, or controller path      | The target app/build and platform run the critical task and negative/recovery trigger with the stated keyboard, controller, adaptive input, or other route; retain the state/event trace and result.                                                        | A requirements artifact, scorer pass, fixture materialization, or a claimed controller/screen reader result without the target runtime. |

Use `planned` for a proposed check and `untested` for an identified combination that was not
exercised. Use `blocked` only after attempting the named setup and recording the specific
missing device, permission, service, dependency, or runtime. Only an observed execution with
matching provenance may be `passed` or `failed`; expected announcements belong in
`expectedObservation`, never in `observedResult`.

For each task and consequential negative state, write the goal, barrier, independently usable alternate route, lost state behavior, recovery invariant, responsible component and priority. A verification row must say what triggers the state, **what can be observed**, the input/AT configuration, the procedure, its status, and who owns remaining risk. When execution cannot occur, use `planned` or `untested`, a null observed result and a null evidence reference. A hypothetical narration string is an _expected_ announcement, not a transcript. A static semantics dump is evidence about the accessibility representation, not evidence of spoken output or alternative input task success. Keep design checks separate from actual manual AT and hardware observations.

See the package's [unexecuted regression oracles](../evals/regression-oracles.md) for the fixed negative paths specific to the fixtures; these do not replace independent runtime verification.
