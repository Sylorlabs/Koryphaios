# Source map

The transferable visual-design contract is intentional hierarchy and coherent execution under real product constraints. Platform guidance supplies medium-specific evidence; competitor/community skills supply useful creative workflow patterns, not universal taste rules.

## Maintained interpretation

- Start with a visual read grounded in the real brief: product/page kind, audience, content, task importance, identity, platform, viewing conditions, existing tokens/components, access needs, density, and motion capability.
- Make hierarchy explain purpose, priority, relationship, and state. Typography, spacing, alignment, grouping, contrast, color, imagery, borders/elevation, radius, and motion should work as a system rather than independent decoration.
- Reuse a sound existing design system when one exists. Novelty is not a requirement; intentionality is. Diverge only when the brief or evidence justifies it.
- Treat generated-design clichés as diagnostic prompts: if a gradient, glass panel, card grid, serif hero, monospace label, extreme asymmetry, or any other familiar treatment is present, be able to explain why it serves this brief. Never convert a current aesthetic tell into a permanent ban.
- Verify complete states with real or representative content: long/localized text, sparse/dense data, loading/progress, errors, empty/disabled states, selection/focus, scale changes, and reduced motion as relevant to the medium.
- Do not fabricate product metrics, testimonials, people, activity, or domain facts to make a design appear complete. Missing content is a constraint to surface, not permission to invent evidence.
- Color cannot be the only carrier of required meaning. Deeper WCAG/platform conformance belongs to the accessibility skills, but the visual direction must not knowingly undermine those requirements.

## Community pattern review

Anthropic's Apache-2.0 `frontend-design` skill is strongest when it asks the model to ground the visual direction in subject matter, inspect its own generic defaults, use restraint, and critique rendered work. Its precise typography heuristics and list of current generated-design tells are time-bound creative heuristics, not standards.

SecondSky's MIT `frontend-design` skill similarly emphasizes a coherent point of view, production-state validation, and avoiding context-free templates. Its fixed breakpoint values, font prohibitions, specific visual styles, and implementation suggestions are web-specific/contextual and are not carried into Kory's cross-medium contract.

Apple HIG guidance is authoritative for Apple platforms and useful evidence for adaptive layout and typographic hierarchy, but it does not define universal rules for Windows, web, terminal, embedded, game/spatial, or other surfaces.
