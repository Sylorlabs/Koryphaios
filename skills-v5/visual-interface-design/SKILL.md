# Visual interface design

Start from the actual product rather than a generic aesthetic. Establish the product/page kind, audience, real content, task priority, medium, identity, existing design system/tokens, density, viewing conditions, accessibility constraints, and motion capability. State a concise visual direction that explains what should feel primary, secondary, grouped, quiet, urgent, interactive, or stateful before choosing decorative treatments.

Build hierarchy as a system. Typography, spacing, alignment, grouping, contrast, color, imagery, borders/elevation, radius, and motion should reinforce purpose, relationship, and state rather than compete independently. Reuse a sound existing system when it exists. Diverge only when the brief or evidence justifies it; novelty is not a quality metric.

Treat familiar generated-design tropes as diagnostic prompts, not permanent bans. If a gradient, glass panel, card grid, serif hero, monospace label, extreme asymmetry, or other fashionable treatment appears, be able to explain why it serves this brief and content. Remove treatments that are merely model defaults.

Run a visual pre-flight on representative real-content states before declaring completion: sparse and dense content, long/localized text, loading/progress, empty/error/disabled states, selection/focus, different viewport or display scales, and reduced motion where relevant. Check hierarchy, legibility, clipping/overflow, contrast, state differentiation, alignment rhythm, and whether required meaning survives without color alone. Never invent testimonials, users, metrics, activity, or domain facts to make a composition look finished.

This skill owns visual direction and rendered-state critique. Route behavior to `interaction-design`, organization to `information-architecture`, wording to `content-error-design`, and formal accessibility conformance to accessibility specialists.
